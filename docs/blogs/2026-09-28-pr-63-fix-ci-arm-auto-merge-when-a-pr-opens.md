## fix(ci): Arm auto-merge when a PR opens

- **Release tag:** `v0.0.32`
- **Source PR:** [#63](https://github.com/mpaulosky/TicketManager/pull/63)

### PR description

Ports mpaulosky/Articles#248, which fixed mpaulosky/Articles#239.

## Problem

`pr-automerge.yml` only armed GitHub auto-merge once a PR was already `CLEAN`. GitHub refuses to arm auto-merge on a clean PR ("clean status"), and nothing re-ran the workflow later, so PRs sat `CLEAN` and unmerged until someone merged them by hand.

## Changes

- `pr-automerge.yml` now arms squash auto-merge as soon as a same-repo PR opens, is marked ready or is updated. A PR that is already `CLEAN` is merged directly, pinned to the head SHA that was checked. Drafts, forks, conflicted PRs and already-armed PRs are skipped.
- The decision logic lives in `scripts/squad/automerge-decision.mjs`, with 11 `node --test` cases run by **Squad Scripts Test**.
- `ci.yml` gets an always-reported **All Tests Passed** gate job. It fails if the build, test discovery or any test job failed or was cancelled, and passes when tests are skipped (Dependabot PRs).

## After merge

The `main` ruleset's required checks become **Build Solution**, **All Tests Passed**, **Analyze (csharp)**. An armed PR then can't merge until its tests and CodeQL pass.

## Validation

`node --test`: 11/11 pass; the cleanup script tests: 27/27. `actionlint` and `yamllint` are clean on the changed workflows (no new findings in `ci.yml`). The PR is opened as a draft, then marked ready once green, so the new workflow merges it itself.
