# Scope the AppHost http launch-profile fix to AppHost.Tests only

- **Release tag:** `v0.0.7`
- **Source PR:** [#14](https://github.com/mpaulosky/TicketManager/pull/14)

## PR description

### Summary

PR #13 fixed `AppHost.Tests` failing in CI (untrusted HTTPS dev cert) but auto-merge landed it on its **first** commit, before a follow-up correction could reach the branch — that first commit pinned `Web`'s launch profile to `"http"` unconditionally in `AppHost.cs`, which broke HTTPS for real local `dotnet run --project src/AppHost` dev sessions, not just the `AppHost.Tests` run it was meant to fix.

This PR scopes the fix correctly:
- `AppHost.cs` only overrides the launch profile when the `WEB_LAUNCH_PROFILE` env var is set — otherwise it uses `AddProject<Projects.Web>("web")` with no override, identical to the pre-#13 default.
- `AppHost.Tests` sets `WEB_LAUNCH_PROFILE=http` on itself (only affecting its own test process) before spinning up the app.

Note: `AddProject<TProject>(name, launchProfileName)` is not a drop-in superset of `AddProject<TProject>(name)` — passing `launchProfileName: null` sets `ExcludeLaunchProfile = true` (excludes launch profiles entirely), which is a different configuration than the default. Verified via a throwaway test that the parameterless overload resolves `web` to both `https` and `http` endpoints (the original default), confirming the conditional branch is necessary, not cosmetic.
