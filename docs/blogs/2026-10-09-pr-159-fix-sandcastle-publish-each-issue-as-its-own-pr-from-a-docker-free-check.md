# fix(sandcastle): Publish each issue as its own PR, from a Docker-free check

- **Release tag:** `v0.0.74`
- **Source PR:** [#159](https://github.com/mpaulosky/TicketManager/pull/159)

## PR description

### Why

A Claude Review of the merged Sandcastle setup (#149) found real problems. The sandbox gate ran Playwright and Aspire
tests that can't run in the image. The SDK pin would break on the next `global.json` bump. The merger closed issues
locally before any push, PR or CI. Untrusted issue text reached agents that held a `GH_TOKEN`. Dependabot didn't cover
the root package. A repeated plan id started two pipelines on one branch. This PR fixes those findings. The `hotfix/`
prefix was fixed in #154 and the `RALPH:` commit prefix in #153; the prompts here keep #153's Conventional Commit
rules. Running `test:sandcastle` in CI is #158.

### What changed

The orchestration is ported from mpaulosky/Articles' redesign, without the flaws its own review found.

- **GitHub stays on the host.** The sandbox gets no token and no `gh`. The host reads the Sandcastle issues and passes
  agents only issues and comments written by owners, members and collaborators. Issue text goes in through prompt
  arguments. `main.mts` refuses to start while `.sandcastle/.env` sets `GH_TOKEN` or `GITHUB_TOKEN`.
- **One draft PR per issue, with `Fixes #n`.** There's no merger and no `gh issue close`. An issue closes only when its
  PR merges through CI and review. An unfinished, failing or rejected issue gets a comment and isn't pushed.
- **A structured reviewer verdict.** The reviewer ends with <code>&#60;verdict&#62;&#123;&#34;approved&#34;&#58; &#8230;&#44; &#34;summary&#34;&#58; &#8230;&#125;&#60;&#47;verdict&#62;</code>. A
  missing or malformed verdict counts as a rejection.
- **`.sandcastle/check.sh`** builds the solution and runs every test project that needs neither Docker nor a browser,
  then the Sandcastle tests. It skips any project that references Testcontainers, `Aspire.Hosting.Testing` or
  Microsoft.Playwright. It finds them in the project file, in the projects it references and in the
  `Directory.Build.*` files above them, so the list isn't hand-kept. The prompts and `CODING_STANDARDS.md` point at
  it instead of `scripts/gate.sh`.
- **Publishing**, avoiding the flaws found in Articles:
  - Before publishing, the host merges `origin/main` into the branch inside the sandbox. A conflict is aborted and
    reported on the issue.
  - It runs the check again whenever HEAD moved after the reviewer or the merge, not only when the reviewer reported
    new commits.
  - It pushes the exact commit the check passed on, from the host checkout, with `core.hooksPath=/dev/null` on every
    host git call, and without force. So an agent-edited hook never runs on the host, and CI runs the full suite.
  - Sandcastle mounts the clone's `.git` read-write into every sandbox. So the host records `.git/config` (and this
    checkout's own `config.worktree`) before any sandbox exists, and refuses to run git or `gh` once they change. If they change, it
    leaves the sandbox running rather than closing it with host git. Host git and `gh` run with `GIT_DIR` and
    `GIT_COMMON_DIR` set, so an agent-written `commondir` can't point them at another config. Every `gh` call names
    the repository with `--repo`. Before closing a sandbox, the host checks that its worktree's `.git` file and
    `commondir` still point where git made them; a run refuses to start while a leftover worktree fails that check.
  - The host's issue comments carry a hidden marker. They're kept out of the owner's comments, and only the latest
    reaches the implementer and reviewer, labelled as Sandcastle's own earlier report.
  - The host reads main's commit id from origin (`ls-remote`) once per round, and uses that id, never
    `refs/remotes/origin/main` (which agents can move), for the check script, new branches, the reviewer's diff and
    the merge. The check runs main's copy of `check.sh` with only root-owned directories on `PATH`; the image installs
    the SDK and pnpm as root. It's a sanity check, not a security boundary: CI and the person who marks the draft
    ready are the gate.
  - A reviewer that leaves uncommitted changes triggers a re-check, which fails on them.
  - The reviewer's summary is fenced in the PR body and issue comments, and its closing keywords are broken with a
    zero-width space, because the description becomes the squash commit's message.
  - A branch already on origin is fetched, and the local branch is created or fast-forwarded to it. A diverged branch
    is reported on the issue and isn't built.
  - The planner runs through `createSandbox` in a worktree on its own branch (`chore/sandcastle-planner`), and its
    sandbox is closed only while the git config is intact. Its branch is reset to main's commit before each plan. Before, it ran in docker()'s default
    `head` mode, which mounts the checkout Sandcastle runs in. No agent touches that checkout any more, so the
    primary-checkout guard #153 added (for the merger, which committed there) is removed along with the merger and
    `merge-prompt.md`.
  - The planner also sees the issues whose PR is open, as a list it can't pick from that still blocks dependents (its
    "everything is blocked" fallback never picks an issue blocked by one in review). An
    issue the implementer finishes without changes gets a comment rather than a silent rebuild every run. A planner
    worktree an interrupted run left behind is removed before the planner's branch is reset.
  - The check and host git ignore replace refs (`--no-replace-objects`, `GIT_NO_REPLACE_OBJECTS`).
  - Fork PRs (`isCrossRepository`) neither hold an issue back nor pass for its PR.
  - Repeated plan ids are dropped.
  - PR titles lose trailing whitespace (`"fix: Foo ."` used to give `"fix: Foo "`).
- **Dockerfile:** installs the latest GA SDK on the 10.0 channel (`--channel 10.0 --quality GA`), as IssueManager
  does, instead of a pin. It no longer installs `gh`.
- **Dependabot:** the npm updater covers `/` as well as `/src/Web`. It leaves Sandcastle's minor and major releases to
  a person, because the prompts' safety relies on Sandcastle 0.12's behaviour; CI (#158) tests the rest.
- **CI:** the Sandcastle tests also run when `scripts/check-pr-title.sh` changes, since `publish.test.mts` runs it.
- **SDK drift:** `check.sh` says when `global.json` needs a newer SDK than the image has, and to rebuild it without the
  cache.

Prompt injection through <code>&#123;&#123;ISSUE&#95;TITLE&#125;&#125;</code> was checked against `@ai-hero/sandcastle` 0.12.0. Its prompt substitution
marks the prompt file's own `` !`…` `` blocks with a `\x01` marker before it fills in the arguments, and strips that
marker from the argument values. Only marked blocks run, so a title containing `` !`cmd` `` stays text. A placeholder
*inside* a shell block would become part of the command, though. A test now keeps every shell block to `BRANCH` and
`BASE_BRANCH`, which the host makes.

**If you run Sandcastle:** remove `GH_TOKEN` from your `.sandcastle/.env` (the guard refuses to start otherwise), and
rebuild the image (`sandcastle docker build-image`).
