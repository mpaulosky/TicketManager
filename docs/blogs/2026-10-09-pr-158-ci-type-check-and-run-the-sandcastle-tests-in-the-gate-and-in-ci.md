# ci: Type-check and run the Sandcastle tests in the gate and in CI

- **Release tag:** `v0.0.72`
- **Source PR:** [#158](https://github.com/mpaulosky/TicketManager/pull/158)

## PR description

### Why

The Sandcastle orchestration code in `.sandcastle/` has node tests (`pnpm run test:sandcastle`), but nothing ran them: not the pre-push gate and not CI. They could regress while every required check stayed green. Claude Review pointed out this gap on #154.

### What changed

- The new `.github/ci/sandcastle.sh` holds the Sandcastle check: which paths count, whether they changed since a base, and the run itself (`pnpm install --frozen-lockfile`, then `pnpm run test:sandcastle`). The paths are `.sandcastle/`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `.npmrc`, `scripts/check-branch-name.sh` (the tests run it) and the three CI scripts. Before installing, the run checks for Node 22.18 or later (23.6 or later on Node 23), the first versions that strip types from `.mts` without a flag, and fails with a clear message on anything older.
- `.github/ci/gate-checks.sh` (the pre-push gate's repo-specific checks) sources that file and runs the check when one of those paths changed since the branch left `origin/main`. If there's no base, it always runs it.
- `.github/ci/prepare.sh build` (CI's **Build Solution** job) sources the same file. On a pull request it uses the same path filter. On a push to main or a manual run it always runs, because HEAD is main there and the diff would always be empty. It runs after the job has already enabled pnpm through corepack, and it uses the runner's own Node. The log line shows the Node version.
- `test:sandcastle` now type-checks `.sandcastle/` with `tsc --noEmit -p .sandcastle` before it runs the tests. This is the same setup Articles uses. It adds `.sandcastle/tsconfig.json` and the dev dependencies `typescript`, `@types/node` and `@standard-schema/spec`. The tsconfig sets `verbatimModuleSyntax` and `erasableSyntaxOnly`, so `tsc` rejects code that Node can't run. `@types/node` is pinned to Node 22, the oldest runtime the tests support, which is also what the Sandcastle sandbox runs. The type check needs `@standard-schema/spec` to type Sandcastle's `Output.object` schemas.
- `docs/CONTRIBUTING.md` and `.github/copilot-instructions.md` say that the gate needs Node 22.18 or later and pnpm for this check.

`gate-checks.sh` and `prepare.sh` are Seed files that the repo owns, so a later Apply of the Baseline won't overwrite them.

### Verification

- `pnpm run test:sandcastle` passes locally: the type check is clean and all 12 tests pass.
- The pre-push gate ran the Sandcastle step on this push ("Sandcastle type check and tests", 12 passed). It then built and tested the solution.
- In CI, the Build Solution job's "Prepare build" step logged `Sandcastle type check and tests (node v22.23.3)` and then `# tests 12`, `# pass 12`, `# fail 0`.
