## fix(web): Find the git root from a linked worktree

- **Release tag:** `v0.0.29`
- **Source PR:** [#57](https://github.com/mpaulosky/TicketManager/pull/57)

### PR description

## Summary

`GitHubMetadataProvider.FindGitRoot` only recognised a `.git` **directory**. In a linked git worktree `.git` is a **file** (`gitdir: …/.git/worktrees/<name>`), so the repo root was never found, the local-git fallback returned `"no release"`, and three `GitHubMetadataProviderTests` failed whenever the pre-push gate ran from a worktree.

## Change

- Accept `.git` as a directory **or** a file.
- `FindGitRoot` is now `internal` so it can be tested directly.
- Two new tests build their own temp layout (a `.git` directory, and a worktree-style `.git` file), so they don't depend on how the test run's checkout is laid out.

## Validation
