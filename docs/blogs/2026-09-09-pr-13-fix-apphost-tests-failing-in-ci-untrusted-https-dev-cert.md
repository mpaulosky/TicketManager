# Fix AppHost.Tests failing in CI: untrusted HTTPS dev cert

- **Release tag:** `v0.0.5`
- **Source PR:** [#13](https://github.com/mpaulosky/TicketManager/pull/13)

## PR description

### Summary
- `AppHost.Tests` fails in GitHub Actions with `AuthenticationException: ... UntrustedRoot` because `AddProject<Projects.Web>("web")` had no explicit launch profile, so Aspire resolved the `web` resource to `Web`'s `https` profile. The dev cert isn't trusted on GitHub-hosted runners.
- Confirmed this is a pre-existing regression on `main` (last several pushes to main were all red on `Tests: AppHost.Tests`), not something introduced by a later PR — it shipped with the already-merged "Scaffold AppHost.Tests and Architecture.Tests" PR.
- Fix: pin the `web` resource to the `http` launch profile in `src/AppHost/AppHost.cs`. Verified locally that the resource now listens on plain HTTP only. This repo has no real HTTPS requirement yet (Tailwind/auth are both already deferred), and the fix is portable — no CI-specific cert-trust workaround needed.

Resolves #12 (a follow-up ticket filed off the [Scaffold TicketManager src/ and tests/ project skeleton](https://github.com/mpaulosky/TicketManager/issues/2) wayfinder map's "Verify full skeleton builds green locally and in CI" ticket), which was blocked on this.
