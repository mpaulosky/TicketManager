## ci: Let blog-posts.json PRs merge, and point Dependabot at the repo root

- **Release tag:** `v0.0.37`
- **Source PR:** [#73](https://github.com/mpaulosky/TicketManager/pull/73)

### PR description

## Blog catalog PRs never merged

`generate-blog-posts-json.yml` pushed `automation/generate-blog-posts-json` with `GITHUB_TOKEN`, and its commit message carried the skip-CI marker. Either one is enough to stop workflows running, so `main`'s required checks never reported and every catalog PR stayed blocked. #56 only merged after someone pushed to its branch by hand, and #72 is stuck the same way now.

- The checkout (so the push too) and the PR creation now use `RELEASE_PR_PAT`, falling back to `GITHUB_TOKEN`. This is the same approach as `release.yml`.
- The commit message no longer carries the skip-CI marker.
- **Loop guard:** the PR title now includes `[skip-release]`, and if an open PR is reused, the marker is added to its title. Without it, `release.yml` writes a release blog for every merged catalog PR (as it did for #56, producing #71), and that blog triggers the generator again.

## Dependabot never updated NuGet or the SDK

The `nuget` and `dotnet-sdk` entries pointed at `/nuget/helpers/lib/NuGetUpdater`, a path that doesn't exist in this repo. Both now use `/`, where `Directory.Packages.props` and `global.json` live. Expect a grouped NuGet update PR on the next weekly run. The 7-day cooldown still applies.
