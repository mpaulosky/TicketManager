# chore: Commit the Sandcastle setup

- **Release tag:** `v0.0.68`
- **Source PR:** [#149](https://github.com/mpaulosky/TicketManager/pull/149)

## PR description

### Why

`.sandcastle/` and the `package.json` that installs `@ai-hero/sandcastle` were never committed, so a fresh clone can't run Sandcastle and prompt changes go unreviewed. Sandcastle expects the folder to be committed, with only its generated files ignored. Blazor-Server already works this way.

### What changed

- `f9860d1` commits the Sandcastle setup:
  - `.sandcastle/`: `Dockerfile`, `main.mts`, the `*-prompt.md` files, `CODING_STANDARDS.md`, `.env.example` and the `.gitignore` that Sandcastle generates (it ignores `.env`, `logs/` and `worktrees/`).
  - `package.json` and `pnpm-lock.yaml`, which pull in `@ai-hero/sandcastle` and `zod`.
  - `.sandcastle/.markdownlint-cli2.jsonc`, copied from Blazor-Server. It turns off MD025 and MD033, because the prompts use a top-level heading per section and inline tags on purpose.
  - One long line in `plan-prompt.md` is split in two for MD013. The text is unchanged and renders the same.

### Verification

- `.env`, `logs/` and `worktrees/` are not in the commit, and every value in `.env.example` is empty.
- The pre-commit markdownlint gate passed: 0 issues across the 5 prompt files.
- The pre-push gate (`scripts/gate.sh`) passed on `f9860d1`.
