# chore(sandcastle): Have agents write Conventional Commits

- **Release tag:** `v0.0.71`
- **Source PR:** [#153](https://github.com/mpaulosky/TicketManager/pull/153)

## PR description

### Why

The Sandcastle implement prompt told agents to start every commit message with `RALPH:`. That breaks the repo's commit
format in `.github/instructions/git-commit-instructions.md`, <code>&#60;type&#62;&#40;&#60;scope&#62;&#41;&#58; &#60;Summary&#62;</code>, so agent commits didn't
match the rest of the history. The review and merge prompts gave no format at all.

### What changed

- `.sandcastle/implement-prompt.md`: the commit section now asks for a <code>&#60;type&#62;&#40;&#60;scope&#62;&#41;&#58; &#60;Summary&#62;</code> subject
  (imperative, capitalized, no closing period, 72 characters or fewer, scoped to the affected project or folder), a
  body wrapped at 72 characters with the task, PRD reference, key decisions, files changed and notes, and
  <code>Refs &#35;&#123;&#123;TASK&#95;ID&#125;&#125;</code> as the last line. It also forbids `--no-verify`, and runs `scripts/gate.sh` after the commit
  rather than before, since the gate's lints only check committed changes.
- `.sandcastle/review-prompt.md`: the refinement commit uses the same format, with <code>Refs &#35;&#60;issue&#62;</code> taken from the
  branch name. It also commits before running the gate, and amends any fix into that commit.
- `.sandcastle/merge-prompt.md`: the merger now writes each merge's message to a file, <code>&#60;type&#62;&#40;&#60;scope&#62;&#41;&#58; &#60;Summary&#62;</code>
  within 72 characters (the issue number and a short title, not the branch name, which can be too long) with
  <code>Refs &#35;&#60;ID&#62;</code> as the last line, and runs <code>git merge &#45;&#45;no&#45;ff &#45;F &#60;file&#62; &#60;branch&#62;</code>, instead of letting `--no-edit` commit
  with Git's default `Merge branch '…'` subject. The file keeps issue titles away from the shell. A conflicted merge
  is concluded with <code>git commit &#45;F &#60;file&#62;</code>, so Git's `# Conflicts:` lines stay out. It runs `scripts/gate.sh` after
  each merge is committed, since the gate's lints only check committed changes, and amends any fix into the merge
  commit. The separate summary commit, which was empty after clean merges, is gone. It also forbids `--no-verify`.
- `.sandcastle/main.mts` and the new `.sandcastle/lib/checkout.mts`: Sandcastle now refuses to start in the primary
  checkout. The merger uses Sandcastle's default `head` strategy, so it commits on the branch checked out where it
  runs, and a clean `git merge` runs no pre-commit hook, so nothing else would stop it merging onto `main`. The check
  is the pre-commit hook's own (git dir equals common dir, unless `baseline.allowPrimaryCommits` is set). Its message
  prints the commands that set up a worktree beside the clone, with quoted paths and a branch new for each run
  (<code>chore&#47;sandcastle&#45;run&#45;&#60;yyyymmddhhmm&#62;</code>), including `pnpm install --frozen-lockfile` and copying `.sandcastle/.env`,
  which a new worktree lacks.

Nothing in `.sandcastle/main.mts` or `.sandcastle/lib/` relied on the `RALPH:` prefix. The orchestrator tracks agent
commits through Sandcastle's run results, not by matching messages, so nothing needed changing for the prefix itself.

- `markdownlint-cli2` on `.sandcastle/*.md`: 0 issues.
