## chore(web): Stop committing the generated app.css

- **Release tag:** `v0.0.43`
- **Source PR:** [#92](https://github.com/mpaulosky/TicketManager/pull/92)

### PR description

Every Tailwind bump from Dependabot left the committed `src/Web/wwwroot/css/app.css` stale. The lockfile moved on, but the CSS in git was still the old build (#89 fixed the latest case by hand). Each local build then regenerated the file and dirtied the tree, which the pre-push gate refuses. CI never noticed, because it regenerates the file too.

The build already produces `app.css` on every run, CI included. So it no longer needs to be in git: it's now untracked and ignored, as in atelier-store.

## Keeping `@Assets["css/app.css"]` working on a clean checkout

`wwwroot/**` is collected when the project first loads, before the build has generated `app.css`. On a clean checkout, the file would therefore be left out of the static-asset manifest, and `@Assets["css/app.css"]` couldn't serve it. I checked: with only the untracking, a clean build's manifest had no `css/app.css` entry. Two changes fix that:
- `TailwindBuild` now runs before `BeforeBuild` (it was before `Build`);
- the target adds the generated file to `@(Content)` right after creating it.

## Validation

- A build with no `bin/`, `obj/`, `node_modules/` or `app.css` now lists `css/app.css` in `staticwebassets.build.json`.
- The pre-push gate passed (build and every test project).

**For existing clones:** after pulling, git deletes the local `app.css`, and the next build recreates it.
