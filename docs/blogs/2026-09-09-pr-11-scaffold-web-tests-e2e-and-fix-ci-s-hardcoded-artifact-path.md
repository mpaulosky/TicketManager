# Scaffold Web.Tests.E2E and fix CI's hardcoded artifact path

- **Release tag:** `v0.0.6`
- **Source PR:** [#11](https://github.com/mpaulosky/TicketManager/pull/11)

## PR description

### Summary
- Scaffolds `tests/Web.Tests.E2E` with one real Playwright smoke test against `Web`'s default template, wired into `TicketManager.slnx`
- Fixes `.github/workflows/ci.yml`'s hardcoded Playwright-diagnostics upload path (`tests/E2E.Tests/...` → `tests/Web.Tests.E2E/...`)
- Adds a CONTRIBUTING.md note on installing Playwright browsers for local `dotnet test` runs

### Notable deviation from the ticket's suggested packages
The pinned `C3D.Extensions.Playwright.AspNetCore.Xunit` (0.1.45, the latest available on NuGet) transitively depends on xUnit **v2** core (via `C3D.Extensions.Logging.Xunit` → `xunit.extensibility.execution` 2.9.2), which collides with this repo's xUnit v3 convention (`xunit.v3.mtp-v2`) — duplicate `IClassFixture<T>`/`FactAttribute` across `xunit.core` 2.x and `xunit.v3.core` (NU1605-style `CS0433` ambiguity).

Used `Microsoft.Playwright.Xunit.v3`'s `PageTest` base class instead (Microsoft's own xUnit-v3-native Playwright adapter, already pinned), paired with a `WebFactory : WebApplicationFactory<Program>` that hosts `Web` on a real Kestrel TCP port via `.UseKestrel(0)`/`.StartServer()` (a first-class `Microsoft.AspNetCore.Mvc.Testing` 10.0 API) so the out-of-process Playwright browser can navigate to it.

Also bumped the `Microsoft.Playwright` CPM pin from 1.59.0 → 1.62.0 — the pinned `Microsoft.Playwright.Xunit.v3` 1.62.0 requires `Microsoft.Playwright >= 1.62.0`, so the old pin caused an `NU1605` package-downgrade error on restore.

Resolves #6 on the [Scaffold TicketManager src/ and tests/ project skeleton](https://github.com/mpaulosky/TicketManager/issues/2) wayfinder map.
