## refactor(web): extract IGitHubRestClient to deduplicate GitHub API access

- **Release tag:** `v0.0.20`
- **Source PR:** [#36](https://github.com/mpaulosky/TicketManager/pull/36)

### PR description

## Summary
- `GitHubProjectsService` and `GitHubMetadataProvider` each hand-rolled the same GitHub REST request headers, auth handling, and catch-and-degrade-to-null policy — extract a single `IGitHubRestClient`/`GitHubRestClient` module that owns the base URL, Accept header, User-Agent, optional bearer token, and resilient GET-and-deserialize-or-null contract, with a warning-level log on any failure.
- `GitHubProjectsService` now owns only its own policy (orgs/users fallback, issue/PR split); `GitHubMetadataProvider` stays static and just swaps its raw `HttpClient` parameter for `IGitHubRestClient`.
- Fixed the stale `"Articles-Web"` User-Agent (left over from before the app was renamed) to `"TicketManager-Web"` while touching every place that set it.
