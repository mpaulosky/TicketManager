## chore(web): Regenerate app.css with Tailwind 4.3.3

- **Release tag:** `v0.0.42`
- **Source PR:** [#89](https://github.com/mpaulosky/TicketManager/pull/89)

### PR description

Dependabot's npm update (#78) raised Tailwind to 4.3.3, but the committed `src/Web/wwwroot/css/app.css` was still the 4.2.1 build. Every local build regenerated it, which left the working tree dirty, so the pre-push gate refused the next push from that checkout.

CI builds skip the Tailwind step (`CI=true`) and use the committed file, so CI never noticed. This PR commits the 4.3.3 output. A second build now leaves the tree clean.

This will happen again with the next Tailwind bump; see the follow-up note in the session summary.
