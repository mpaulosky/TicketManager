## fix(ci): Let the release workflow open its docs-failure tracker

- **Release tag:** `v0.0.34`
- **Source PR:** [#67](https://github.com/mpaulosky/TicketManager/pull/67)

### PR description

## Problem

The **Report docs generation failure** step, added in #30, opens or comments on a `Release docs generation is failing` issue when the release blog can't be generated. But `release.yml` never had `issues: write`, so the first real docs failure would get a **403** and file nothing, which is exactly the silent failure #30 was meant to prevent. The step has never fired, and no tracker issue exists, so this went unnoticed.

## Change

Add `issues: write` to the workflow's permissions.

Found while backporting the step to mpaulosky/Articles#255, which ships it with the permission.

`actionlint` and `yamllint` are clean, with the same 2 existing shellcheck notes as `main`.
