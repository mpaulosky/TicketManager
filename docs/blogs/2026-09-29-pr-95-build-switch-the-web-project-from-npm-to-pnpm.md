## build: switch the web project from npm to pnpm

- **Release tag:** `v0.0.44`
- **Source PR:** [#95](https://github.com/mpaulosky/TicketManager/pull/95)

### PR description

_Requested by **Matthew** · [project thread](https://claude.ai/code/project/chan_01M4TRjuaTvMLM1jqeNd9KNs?thread=cmsg_01M4TRjuaTvMLM1jqeNd9KNsBqvSH7Zyjxovd4Kr4rap1i)_

Before: the Tailwind CLI in `src/Web` was installed and run with npm (`npm ci`, `npx @tailwindcss/cli`), and CI, CodeQL, the gate script and the Copilot MCP config all called npm or npx.

After: `src/Web` uses pnpm 12.6.0, pinned through `packageManager`, with a committed `pnpm-lock.yaml`. `npm install` there now fails on purpose (`engines.npm` + `engine-strict`), matching atelier-store.

The lockfile was converted with `pnpm import`, so every resolved version is unchanged (Tailwind stays at 4.3.3).

How:
- `package.json`: scripts call the `tailwindcss` bin directly; adds `packageManager` and the npm engine block. New `.npmrc` and `pnpm-workspace.yaml` (`@parcel/watcher` build script is not needed, so it stays disabled).
- `Web.csproj`: `NpmCommand` → `PnpmCommand`, `pnpm install --frozen-lockfile`, stamp input is `pnpm-lock.yaml`.
- `ci.yml` (build and test jobs) and `codeql-analysis.yml`: `pnpm/action-setup` (SHA-pinned, reads the version from `package.json`), `setup-node` with `cache: pnpm`, `pnpm install --frozen-lockfile`.
- `scripts/gate.sh`, pre-commit hint, `copilot-instructions.md`, `.github/mcp-config.json`: `npx` → `pnpm dlx`.
- Dependabot keeps `package-ecosystem: "npm"`, which covers pnpm lockfiles.

Verified locally from a clean tree: `scripts/gate.sh` passed (YAML, actionlint, zizmor, shellcheck on the changed files, Release build, and all six test projects including Integration and E2E). A second build leaves the tree clean.
