# build(deps): Fail restore on vulnerable NuGet packages

- **Release tag:** `v0.0.95`
- **Source PR:** [#207](https://github.com/mpaulosky/TicketManager/pull/207)

## PR description

### Why

#205 turned the NuGet audit warnings back on, but TicketManager doesn't set `TreatWarningsAsErrors`. So a vulnerable package only shows up as a restore warning, and the build still passes. Articles and Blazor-Server fail the build on an advisory, and this makes TicketManager do the same.

### What changed

- `Directory.Packages.props`: add NU1901, NU1902, NU1903 and NU1904 (low, moderate, high and critical) to `WarningsAsErrors`. NuGet applies this to restore, so it also covers transitive packages.
- Only those four codes become errors. The repo doesn't turn on `TreatWarningsAsErrors`, so compiler and analyzer warnings stay warnings.

The trade-off is the one accepted for Articles in #337: when an advisory is published for any package in the graph, every restore fails until someone pins a patched version.

### Verification

- With the current packages, `dotnet restore TicketManager.slnx --force` succeeds with no NU190x diagnostics.
- With MessagePack temporarily set back to the vulnerable 2.5.302, restore fails with `error NU1902: Warning As Error: Package 'MessagePack' 2.5.302 has a known moderate severity vulnerability`. Restoring 2.5.307 makes it pass again.
- The pre-push gate passed.
