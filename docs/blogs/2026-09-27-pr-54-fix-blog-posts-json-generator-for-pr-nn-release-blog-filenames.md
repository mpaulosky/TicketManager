## Fix blog-posts.json generator for pr-NN release blog filenames

- **Release tag:** `v0.0.28`
- **Source PR:** [#54](https://github.com/mpaulosky/TicketManager/pull/54)

### PR description

## Problem
The **Generate blog posts JSON** workflow has failed on every run since 2026-09-12 with:

```
ValueError: Unexpected blog filename format: 2026-09-12-pr-44-chore-deps-update-aspire-apphost-sdk-to-13-5-3.md
```

The generator only accepted `YYYY-MM-DD-NN-slug.md`, but release blogs are named `YYYY-MM-DD-pr-NN-slug.md`. It also failed on `docs/blogs/README.md`, which isn't a post. As a result, `docs/data/blog-posts.json` hasn't picked up any new post since 2026-09-09.

## Changes
- `.github/scripts/generate-blog-posts-json.py`: accept both filename forms. For `pr-NN` posts, the PR number becomes the `sequence` used to sort posts within a date. The script also skips `README.md`.
- `docs/data/blog-posts.json`: regenerated. It now lists all 25 posts. This PR includes the file because changes to the script don't trigger the workflow.

## Note
Even after this fix, the workflow's step that opens a PR will fail until the repo setting **Allow GitHub Actions to create and approve pull requests** is enabled. Its runs on Sep 11 failed with `GitHub Actions is not permitted to create or approve pull requests`, and so did the sync-readme workflow's.
