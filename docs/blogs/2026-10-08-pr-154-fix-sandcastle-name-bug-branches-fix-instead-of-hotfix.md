# fix(sandcastle): Name bug branches fix/ instead of hotfix/

- **Release tag:** `v0.0.69`
- **Source PR:** [#154](https://github.com/mpaulosky/TicketManager/pull/154)

## PR description

### Why

Sandcastle named every bug issue's branch <code>hotfix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>. docs/PROCESS.md uses `fix/` for a bug fix and keeps `hotfix/` for an urgent fix, and the repo has no label that marks a bug as urgent, so bugs should land on `fix/`.

### What changed

- `.sandcastle/lib/branches.mts`: a `bug` label now gives <code>fix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>; anything else still gives <code>feature&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>. One list of issue prefixes (`feature`, `fix`, `hotfix`) drives both `isIssueBranch` and `localIssueBranches`, so an issue's existing `fix/` or `hotfix/` branch is still found and reused rather than orphaned.
- `.sandcastle/lib/branches.test.mts`: expects `fix/` for bugs, checks `fix/` and `hotfix/` branches are recognized and reused. The existing test still runs every generated name through `scripts/check-branch-name.sh`.

No prompt mentions `hotfix/`, so no prompt changes. Mirrors mpaulosky/Articles#308.
