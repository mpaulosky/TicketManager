## fix(docs): Rebase README links in the docs/ copy

- **Release tag:** `v0.0.47`
- **Source PR:** [#104](https://github.com/mpaulosky/TicketManager/pull/104)

### PR description

## Why

`docs/README.md` is the root README copied into `docs/`, and both the release workflow and the README sync copied it verbatim. Relative links written from the root (`docs/blogs/x.md`, `LICENSE`) then pointed one directory too deep (`docs/docs/blogs/x.md`, `docs/LICENSE`) and 404'd. Copilot flagged it on every release-blog PR.

## What

- New `.github/scripts/docs_readme.py` writes the copy with relative link targets rebased for `docs/`: a `docs/` prefix is dropped and anything else gets `../`. It covers Markdown links, reference definitions and HTML `src`/`href`. Absolute URLs, anchors, root-relative paths and fenced code are left alone.
- `release.yml` and `sync-readme.yml` use the script instead of a verbatim copy.
- New **Docs README Tests** workflow runs the script's unittest suite.
- `docs/README.md` regenerated from the current `README.md`.

## Notes

Supersedes the earlier `chore/docs-readme-links` branch (never opened as a PR). It was 9 commits behind `main` and conflicted on the generated `docs/README.md`, so the commit was cherry-picked onto current `main` and `docs/README.md` regenerated with the script.
