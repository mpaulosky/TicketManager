## fix(apphost): revert AspireUseCliBundle to avoid breaking CI

- **Release tag:** `v0.0.25`
- **Source PR:** [#46](https://github.com/mpaulosky/TicketManager/pull/46)

### PR description

## Summary
- PR #44 enabled `AspireUseCliBundle=true` in AppHost.csproj to silence the ASPIRE010 warning from the 13.5.3 SDK bump.
- That setting broke CI's CodeQL "Analyze (csharp)" job with `ASPIRE009: AppHost is configured to use the Aspire CLI bundle, but the bundle could not be resolved` — that runner doesn't have the Aspire CLI installed.
- Reverted to `NoWarn` suppression of ASPIRE010 instead, which keeps the build warning-free without requiring the CLI bundle at build time.
